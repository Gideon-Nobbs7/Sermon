How it works

  1. Parse. Your files become searchable chunks. Dated notes keep their speaker, topic, and scripture metadata; PDFs and Word docs are split into passages automatically.
  2. Embed. Each chunk is embedded and stored in a single SQLite file.
  3. Retrieve. Your question pulls the 5 most relevant passages.
  4. Answer. The model replies from those passages only, with citations.

Things you can ask

  • Question answeringAnswers with date and speaker attached.
  • Scripture lookupFind where a verse was taught, quoted in full.
  • Speaker filterLimit answers to one teacher.
  • Date rangesSearch a series or a month.
  • Topic discoverySee everything taught on a theme.
  • Auto-updatesDrop new files into the data folder (notes, PDFs, Word docs) and they index themselves.

One container on any VPS

Docker for the easy path, plain Python for full control. The watcher and the web server run side by side; one SQLite file holds everything.

Common questions

Where do the answers come from?

Only from your indexed sermon notes and the King James text bundled with the app. If the notes do not cover it, the bot says so.

What does it cost to run?

Embeddings and answers use your own API keys, so usage decides the bill. The app itself is one small container with a single SQLite file.

Do I need WhatsApp approval to start?

No. Telegram works as soon as you set the webhook. WhatsApp starts in a sandbox and moves to production review later.

What happens when providers go down?

Each call is time-boxed and falls back to a second provider, so one outage does not take the bot down.

Where is my data kept?

In your own data/sermons.db on your own machine or VPS. Nothing is shared unless you share it.
